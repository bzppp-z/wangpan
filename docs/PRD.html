多用户网盘 · MVP 需求文档

多账户 · Windows 客户端（Qt 5.12）+ 阿里云服务器 · 面向自己与朋友的公网网盘，兼作秋招作品
版本 v0.3（需求已确认） 日期 2026-11-03 范围：骨架 + 多用户 + 在线预览 部署目标：阿里云公网

0. 阅读说明

本文只定义产品行为：用户能做什么、在什么条件下做、结果是什么、出错怎么办。不涉及接口、数据库、代码结构（那些在开发阶段单独定）。

标记约定：TBD 表示尚未决定、需要你拍板的事项，汇总在第 6 节；FR-xx 是功能编号，后续开发与验收都按编号对齐。

产品定位小规模多用户网盘
用户规模多账户（自己 + 朋友），每人独立空间
核心价值文件存自己的服务器，公网随时取回
附加价值完整可讲的项目（客户端 + 服务端 + 部署 + 多用户）

1. 背景与目标

1.1 背景

文件分散在本地电脑、移动硬盘和聊天工具里，缺少一处"随时能取回"的位置；同时已有一台阿里云服务器长期闲置。

产品从"只给自己用"调整为"部署到公网、可以给朋友一起用"：服务器、域名和带宽的钱已经花了，多账户带来的增量成本有限，却能让系统更完整。

做这个产品有两层动机：实用——把自己的文件集中到一个自己可控的地方，并让朋友也能用；作品——它是一个覆盖客户端、服务端、部署、公网访问的完整项目，适合作为秋招简历与面试讲解的载体。

由此产生的一个约束：这个项目要"讲得清"。凡是自己说不明白原理的功能，宁可不做，也不要把别人的代码贴进来当自己的。文档里的每条规则，最终都应该能对应到一段你能解释的代码。

1.2 目标（按可见结果描述）

编号目标可观察的完成标志
G1能登录并看到服务器上的目录内容登录后主界面列出根目录下的文件与文件夹；进入子目录能看到对应内容
G2能把本地文件上传到服务器，大文件也不例外上传完成后列表中出现的文件大小与原文件一致；实际下载回来字节完全相同
G3上传/下载中断后可以继续，而不是从头再来断网或关闭客户端后重新打开，任务仍可"继续"，且只补传缺失部分
G4同一个文件重复上传不重复占用空间第二次上传同一文件时任务显示"秒传"，瞬间完成
G5不用下载就能看图片和文本内容双击图片/文本文件，客户端内直接显示内容
G6误删的文件可以找回删除后文件出现在回收站，可恢复到原目录
G7多个账户互不干扰用自己的账号登录只看到自己的文件；换个账号登录看不到前一个账号的任何内容

2. 范围

2.1 核心用户旅程

环节内容
入口打开客户端 → 填写服务器地址 → 注册或登录（首次使用先注册）
主路径浏览目录 → 上传文件（大文件自动分片）→ 列表中出现该文件 → 双击预览 → 需要时下载回本地 → 删除进回收站
完成证据文件出现在远程列表且大小正确；下载回来的文件与原文件字节一致；预览能显示内容；回收站里能恢复
失败恢复传输中断 → 任务变为"已暂停" → 重新登录后点"继续" → 只补传缺失分片

2.2 本期必做（P0）

编号功能为什么必须在第一期
FR-00注册多用户的前提；没有注册就只能手工开号
FR-01登录区分账户身份；所有文件操作都以登录账户为边界
FR-02目录浏览网盘的"结构"就是目录树，其余功能都挂在它上面
FR-03新建文件夹没有它，文件只能堆在根目录，无法组织
FR-04重命名最基础的整理动作，成本极低
FR-05删除与回收站防误删是真实需求；软删除的实现成本很低
FR-06上传（分片）核心能力，也是最能讲的技术点
FR-07断点续传没有它，大文件一断网就白传，体验直接崩
FR-08秒传与分片共用一套机制，顺带做出"网盘感"
FR-09下载（断点续传）上传的对称面，不做就等于存进去拿不回来
FR-10传输队列多文件、大文件场景下必须能看到进度与暂停
FR-11在线预览（图片 / 文本）你明确要求本期做；限制在两类以实现成本可控

2.3 本期不做（并说明为什么现在不做）

不做原因
管理员后台、审计日志、角色权限（管理员/只读等）多账户已进本期，但"后台管理"是另一套系统；本期用固定配额 + 直接改数据库即可
分享链接、Web 端、手机端你已明确不做 Web；分享是独立功能，可在骨架之上追加
HTTPS本期先用 HTTP，风险已在第 6 节记录；正式公网长期使用前必须补
本地文件夹自动同步（双向）需要文件监听、冲突解决、增量对比，是网盘最难的部分，成本数倍于本期全部内容
多节点 / 分布式存储单机就能满足本期规模；分布式是另一个量级的工程，宁可后续接现成对象存储也不手写
版本历史需要保留多份内容与清理策略，与"回收站"一起做会更复杂
视频 / Office / PDF 预览需要转码或专用渲染，先只做图片与文本
批量打包下载需要服务端打包，属于独立功能；单文件下载已够用

3. 产品模型

3.1 对象

对象定义用户可见的关键信息
账户一个注册用户，拥有独立的文件空间与配额用户名、登录状态、已用空间 / 配额
文件一个带名称的节点，属于某个账户下的某个目录名称、大小、修改时间、类型
文件夹可以包含文件与文件夹的节点，同样归属于某个账户名称、修改时间
文件内容文件的实际数据。相同内容只保存一份，多个文件条目可共用不可见（用户只看到文件条目）
传输任务一次上传或下载的执行记录方向、大小、进度、速度、剩余时间、状态
回收站条目被删除但尚未彻底清除的文件或文件夹名称、删除时间、原所在目录

3.2 状态

传输任务

状态含义可执行操作可流转到
等待中已创建，尚未开始传数据取消进行中 / 已取消
进行中正在上传或下载暂停、取消已暂停 / 已完成 / 失败 / 已取消
已暂停用户暂停或网络中断后自动暂停，已传部分保留继续、取消进行中 / 已取消
校验中数据已传完，正在确认内容完整取消已完成 / 失败
已完成成功结束清空记录、打开所在位置—
失败校验不通过、服务器错误、磁盘不足等重试、删除记录进行中（重试）
已取消用户主动取消，已传部分立即清理重新开始等待中

文件

状态可见位置可执行操作
正常所在目录预览、下载、重命名、删除（目录间移动不在本期）
回收站回收站恢复、彻底删除
已彻底删除不可见无（不可恢复）

3.3 共享规则（全篇只在这里定义一次）

编号规则
R0 账户隔离每个账户只能看到、只能操作自己的文件与回收站。所有列表与文件操作都以当前登录账户为边界；越权访问按"文件不存在"处理，不透露它是否存在。
R1 内容去重相同内容在服务器上只保存一份，但每个账户的文件条目互相独立。删除一个条目只影响该条目本身，不会让其他账户的文件失效；去重不改变可见性与访问边界（见 R0、R10）。
R2 重名处理同一目录下不允许同名。上传、新建、重命名、恢复到原目录时遇到重名，自动在名称后追加 (1)、 (2)…
R3 回收站保留保留 30 天，超期自动彻底删除；清空回收站不可恢复。
R4 分片与上限单文件上限 10 GB；分片 4 MiB；上传会话在服务端保留 7 天，超期后任务必须从头开始。
R5 预览不落盘预览直接读取远程内容，不要求用户先下载；产生的本地临时数据在预览关闭后清理。
R6 时间显示列表中的时间按客户端本地时区显示，精确到分钟。
R7 命名校验名称长度 1~255 字符，禁止 / \ : * ? " < > | 与首尾空格；空名称与纯空格被拒绝。
R8 删除确认删除到回收站不需要二次确认（可恢复）；彻底删除与清空回收站必须二次确认。
R9 空间配额每个账户默认 5 GB；超出后上传被拒绝并提示"空间不足"；回收站中的文件计入已用空间，直到彻底删除。
R10 秒传范围秒传只在"该账户已拥有同内容文件"时成立，不允许通过内容校验值把其他账户的文件变成自己的条目。
R11 登录会话登录成功后获得访问凭证，有效期 7 天；过期后需重新登录。同一账户允许在多台设备同时登录。

4. 功能需求

FR-00注册

目的：让新用户能自己创建账户，而不是由你手工开号。

项定义
触发登录界面点击"注册"；未登录状态下可见
输入服务器地址、用户名、密码
规则用户名 3~20 位，仅字母数字下划线，全局唯一；密码 6~64 位；用户名已存在 → 提示"该用户名已被使用"
结果注册成功 → 自动登录并进入主界面，根目录为空
异常服务器不可达 → 提示无法连接；用户名已被占用 → 提示"该用户名已被使用"；重复提交 → 只创建一次账户
配额初值新账户已用空间为 0，配额按 R9 赋默认值

FR-01登录

目的：识别当前使用者是谁，让所有文件操作都有明确的归属，避免服务器被匿名访问。

项定义
触发客户端启动且未登录；或主动点击"切换账号"
输入服务器地址（默认 http://127.0.0.1:8080）、账号、密码
规则地址与账号在下次启动时回填；密码不持久化
结果登录成功 → 进入主界面并加载根目录
异常账号或密码错误 → 统一提示"账号或密码错误"（不区分哪一项错）；服务器不可达 → "无法连接服务器，请检查地址"；10 秒无响应按超时处理；连续失败不锁定
退出主界面"退出登录" → 回到登录界面并清除本地访问凭证；未完成的传输任务保留

FR-02目录浏览

目的：让用户看到服务器上有什么，并能进出各级目录。

项定义
触发登录成功后自动加载根目录；点击文件夹、面包屑、返回；点击"刷新"
展示列表列：名称、大小（文件夹显示"—"）、修改时间、类型；文件夹排在文件前面；只显示当前账户拥有的条目
排序默认按名称升序；支持点列头切换
结果双击文件夹进入；双击文件触发预览；面包屑显示当前路径
异常空目录 → 显示"这个文件夹还是空的"；加载失败 → 显示错误信息与"重试"；目录已被删除 → 提示并回到根目录
刷新上传/删除/重命名完成后局部刷新，保持当前路径与选中项（若仍存在）

FR-03新建文件夹

项定义
触发工具栏"新建文件夹"或列表右键菜单
输入名称，遵循 R7
规则重名按 R2 自动追加序号；名称为空或非法 → 输入框标红并提示，不发起请求
结果新文件夹出现在当前目录并选中
异常服务端失败 → 提示原因，输入框内容保留以便重试

FR-04重命名

项定义
触发选中单个条目后按 F2 / 右键"重命名"
规则遵循 R7 与 R2；只允许单个条目，多选时该操作不可用
结果列表中原位置更新名称；当前位置与选中状态不变
异常名称未变化 → 不发请求；目标已存在 → 自动追加序号（按 R2）

FR-05删除与回收站

项定义
触发选中一个或多个条目后删除；回收站中"恢复"或"彻底删除"
规则删除 = 移入回收站（R8，不二次确认）；删除文件夹时其内部内容一并进回收站；恢复时原目录已不存在则恢复到根目录，重名按 R2；彻底删除需二次确认（R8）
结果条目从当前目录消失；回收站中可看到并可恢复；恢复后回到原目录原名称（或按 R2 改名）
异常条目已不存在 → 提示"文件已被删除"并刷新列表
容量回收站中的文件计入已用空间，直到彻底删除（见 R9）

FR-06上传

目的：把本地文件存到服务器，任意大小都能成功。

项定义
触发工具栏"上传"、拖拽文件到列表、右键菜单；支持一次选多个文件；支持选择一个文件夹，按原有目录结构递归上传
流程① 客户端计算文件的内容校验值（带进度，不阻塞界面）→ ② 向服务器发起上传，若同内容已存在则秒传（FR-08）→ ③ 否则按分片顺序上传 → ④ 服务端拼接并校验 → ⑤ 生成文件条目
结果列表出现该文件；任务状态变为"已完成"；大小与原文件一致
异常网络中断 → 任务自动转"已暂停"，可继续（FR-07）；内容校验不通过 → 任务"失败"，提示"文件可能在传输中损坏，请重新上传"；超出配额 → 失败并提示"空间不足"；同名 → 按 R2 自动改名
界面反馈进度、速度、剩余时间；秒传时显示"秒传完成"

FR-07断点续传

项定义
触发任务处于"已暂停"（用户手动暂停或网络中断自动暂停），用户点"继续"
规则服务端记录本次上传已收到哪些分片；继续时只补传缺失分片；已完成的分片不重复上传
结果进度从已上传的位置接着走，不归零
异常上传会话已过期（R4）→ 提示"上传会话已失效，将重新开始"，进度归零重传；分片在服务端丢失 → 该分片重传
跨会话关闭客户端后未完成任务保留在传输列表；重新打开并登录后可继续

FR-08秒传

项定义
触发上传流程第②步：服务端发现已有相同内容的文件
规则不传输文件数据，仅创建新的文件条目（可以放在其他目录，也可以使用其他名称）
结果任务立即变为"已完成"，并标记"秒传"
边界秒传只影响"传不传数据"，不影响条目数量与用户可见的文件名；删除其中一个条目不影响其他条目（R1）

FR-09下载

项定义
触发选中文件后点击"下载"；选择保存位置（默认上次使用的目录，首次为系统"下载"文件夹）
规则支持断点续传；暂停后继续只补缺失部分；下载中可取消
结果完成后本地文件可正常打开；文件名默认为远程名称，重名按 R2
异常文件已被删除 → 提示并刷新；磁盘空间不足 → 失败并提示；取消后删除未完成的临时文件
暂不支持文件夹整体下载、多选批量下载（见 2.3）

FR-10传输队列

目的：让用户随时知道"在传什么、传了多少、还要多久"，并能控制它。

项定义
展示每个任务一行：文件名、方向（上传/下载）、总大小、进度、速度、剩余时间、状态
操作暂停、继续、取消、重试、清空已完成记录、打开所在位置
并发同时进行的任务数上限 3；超出部分排队为"等待中"
规则暂停保留已传数据；失败自动重试 3 次，仍失败才置为"失败"；取消为终态，需重新创建任务
持久化未完成任务在关闭客户端后保留，重新打开可见并可继续；已完成记录仅在本次会话内保留，重启后清空

FR-11在线预览

目的：不下载就能确认内容，省时省空间。

项定义
触发双击文件，或右键"预览"；仅对文件生效，文件夹双击为进入
支持类型图片：png、jpg、jpeg、gif、bmp、webp；文本：txt、md、log、json、xml、csv、cpp、h。PDF 本期不做
文本规则只读展示，等宽字体；超过 1 MB 时截断并提示"文件过大，仅显示前 1 MB"
图片规则适应窗口显示，滚轮缩放；不支持的格式提示"暂不支持预览，请下载后查看"
展示位置主界面右侧预览面板
异常加载中显示占位与进度；文件已被删除 → 提示并刷新；加载失败 → 可重试

6. 决策记录

#问题影响我的建议
Q1主界面布局：左侧目录树 + 右侧文件列表，还是单栏文件列表（靠面包屑导航）？整体布局，改动成本最高，越早定越好左侧目录树 + 右侧列表，最像网盘，也最能体现数据结构
Q2登录：独立启动窗口，还是主界面顶部的登录栏？启动流程与首屏体验独立登录页，登录成功后进入主界面
Q3传输进度放在哪：主界面底部状态栏摘要 + 独立"传输列表"页签，还是直接在文件列表里显示进度条？信息密度与实现复杂度底部摘要 + 可展开的传输列表
Q4预览是独立窗口，还是主界面右侧面板？是否要重构布局右侧面板（像网盘），但随着列表变窄需要适配
Q5上传入口要哪些：按钮、拖拽、右键？交互实现量三者都要，拖拽体验最好
Q6要不要文件夹上传（选一个文件夹递归上传）？会增加 P0 工作量，但简历上多一个点建议做，成本中等
Q7文件名重名时自动加 (1)，还是弹窗问"覆盖/两者都留"？影响上传、下载、恢复等多处自动加序号，不打断流程
Q8回收站保留多久？是否需要"清空回收站"？涉及定时清理保留 30 天 + 手动清空
Q9单文件大小上限、分片大小、并发任务数？性能与内存占用上限 10 GB、分片 4 MB、并发 3
Q10文本预览上限 1 MB 是否够？要不要支持 PDF？预览模块范围文本 1 MB；PDF 先不做
Q11服务器地址写在登录页，还是放到设置页/配置文件？换服务器是否要重新登录写登录页，同时记住上次的值
Q12简历上你最想突出哪个技术点：分片上传与断点续传、内容去重（秒传）、并发传输、还是服务端部署？决定我们把哪块做深、写细主推"分片 + 断点续传"，其余作为支撑

#决策说明
M1开放注册任何人都可注册，本期不做邀请码。已知风险：可能被陌生人或爬虫注册，占用磁盘与带宽。
M2每账户 5 GB回收站占用计入配额；个别账户需要时单独调大。
M3本期使用 HTTP，不启用 HTTPS已知风险：账号、密码、文件内容在公网传输时为明文。仅限小范围可信使用，正式长期使用前必须补 HTTPS。
M4客户端以"免安装文件夹"分发用 windeployqt 收集依赖 DLL，压缩后发下载链接，朋友解压即用。
已接受的风险，请记住：HTTP 是明文传输，同一网络里的人可以截获密码和文件内容。本期你选择先不上 HTTPS，可以接受；但只要服务端放到公网、能被别人访问，就应该尽快补上（买域名 + 免费证书，改动量很小）。这不是功能，是上线前的安全底线。

7. 术语

术语含义
分片把一个大文件切成固定大小的块，逐块传输
断点续传传输中断后，从已完成的进度继续，而不是从头开始
秒传服务器已有相同内容的文件，新文件不再传输数据，直接生成条目
内容校验值由文件内容算出的定长字符串，内容相同则值相同，用于判断"是不是同一个文件"
回收站删除后的暂存区，条目仍占用存储，可恢复
